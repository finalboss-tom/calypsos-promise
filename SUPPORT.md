# Project Communication and Support

Calypso’s Promise handles public project communication through GitHub.

Use:

- GitHub issues for public-safe bugs, proposals, documentation, accessibility, governance, and other project work;
- pull requests for reviewable repository changes;
- the System challenge or revalidation request form for public-safe challenges to assumptions, metrics, incentives, policies, architecture, decisions, or institutional mechanisms;
- `SECURITY.md` for vulnerabilities, exposed credentials, privacy incidents, and other security-sensitive matters; and
- `CODE_OF_CONDUCT.md` for conduct matters.

No personal email address is an official project contact or support channel. Do not publish a maintainer’s private contact information in issues, pull requests, documentation, commits, screenshots, logs, or examples.

Protected health, account, legal, personnel, correspondence, negotiation, conduct-evidence, and production information must not be placed in public GitHub surfaces. Use only an authorized private route when one exists. The absence of an approved private route is a launch blocker, not permission to publish protected material.

Developer Certificate of Origin sign-offs certify authorship and contribution rights; they are not communication channels. Contributors who do not want a personal address exposed in public commit history should configure and use their GitHub-provided noreply address before committing.
